Documentation

loupe does one job: read a change carefully, annotate it, and hand the result to a coding agent. It runs entirely on your machine, with no accounts or uploads.

@@ install @@

loupe runs on Bun (1.0+) and needs git on your PATH.

$ git clone https://github.com/codywilliamson/loupe $ cd loupe $ bun install $ bun link # puts `loupe` on your PATH — macOS, Linux, Windows

Then run loupe from any git repository.

Windows fallback — if loupe isn't found after bun link (it depends on how Bun was installed), add a function to your PowerShell profile instead:
'function loupe { bun "C:\path\to\loupe\src\index.ts" @args }' | Add-Content $PROFILE

@@ review with an agent @@

Install the Claude Code integration from the Loupe repository root:

$ claude plugin marketplace add . $ claude plugin install loupe-review@loupe-local --scope user

Start a new Claude session, ask it to Review my current changes with Loupe., then comment in the browser and choose Return Feedback. Back in Claude, say continue. After it edits and requests rereview, Loupe shows the agent's replies as they arrive; load the new diff from the notice, reply in or resolve the addressed threads, and approve or return more feedback.

Codex follows the same flow. See the repository README for its marketplace commands.

@@ radar @@

Radar ranks an agent's change into review units. Deterministic Git evidence sets known boundaries and blockers; live Jev decisions then rank the remaining semantic uncertainty. Every rank stays inspectable — typed probabilities, provenance, and the exact redacted request — and secret-shaped code is blocked locally and never transmitted. Experimental; off by default.

@@ usage @@

Run loupe inside the repo you want to review. It prints a localhost URL and opens your browser — the diff renders there, not in the terminal.

@@ reviewing @@

Line comments

Hover any line and press the bubble to comment. To comment on a range, drag across the line numbers (or shift-click a second line). In side-by-side view you can comment on either pane — removed lines included — and the export labels them Old line N.

Tags

Each comment can carry an intent tag — nit, issue, question, or praise. Tags show as pills in the UI and become **[tag]** prefixes in copied Markdown, so the model knows intent.

Resolving

Done with a comment but want to keep it? Resolve it instead of deleting — it stays in the thread, dimmed, but drops out of returned feedback and the open-comment counts, and reopens with one click. Handy mid-loop: after an agent addresses your notes, resolve what's done so only open feedback remains.

Orphaned comments

Comments anchor to a line or file in the diff. When the code moves on — you push, then make more unrelated changes — a comment's anchor can leave the current diff. Rather than vanish or silently bloat current feedback, these orphaned comments are gathered in the feedback dialog under From earlier reviews, each with resolve and delete. They're kept out of copied feedback, so stale notes from earlier work never leak into the current review.

File-level comments & viewed tracking

The speech-bubble button in a file header attaches a comment to the whole file. The checkbox in the sidebar marks a file viewed; a progress bar above the tree tracks how much of the diff you've read. The filter box narrows the tree to matching paths.

Live refresh

The refresh button (or reloading the tab) re-runs the diff in place while keeping your comments — useful while an agent keeps editing under you.

@@ appearance @@

The theme button toggles between a light paper palette and a dark charcoal palette. Your choice persists under loupe-theme; the first run follows your OS preference.

@@ feedback handoff @@

Preview Feedback assembles every open comment into ordered markdown: file-level notes first, then line comments sorted by position, each wrapped in ±2 lines of diff context with the commented range marked by >. Resolved and orphaned comments are left out.

@@ review records @@

Comments, replies, viewed-state, summaries, and outcomes persist under ~/.loupe/reviews/<review-id>/review.json. Review data stays local and outside the repository, and completed reviews remain until you explicitly remove them.

If Loupe finds an older .review file, it leaves it untouched and asks whether to import it, remove it with confirmation, or ignore it.

@@ staying updated @@

loupe checks its own repo for newer release tags (throttled, fully offline-safe). When one exists, a pulsing dot appears next to the wordmark — click it for the exact git pull command. Updating is just pulling the repo you cloned.
