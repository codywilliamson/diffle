nittle ships as a single self-contained binary: it embeds its own web client and needs no checkout, no Node, and no sidecar files. It does need **`git`** on your `PATH` — that's the only prerequisite.

## Install

<Tabs syncKey="os">
  <TabItem label="macOS / Linux" icon="apple">
    ```sh
    curl -fsSL https://nittle.dev/install | sh
    ```
  </TabItem>
  <TabItem label="Windows" icon="seti:powershell">
    ```powershell
    irm https://nittle.dev/install.ps1 | iex
    ```
  </TabItem>
</Tabs>

The installer downloads the binary for your OS and architecture, verifies its SHA-256 against the published checksum manifest, and installs it to `~/.nittle/bin` — and adds that directory to your `PATH` for you.

<Aside type="tip" title="Custom location">
  Set `NITTLE_INSTALL_DIR` before running the installer to choose a different directory.
</Aside>

<Aside type="note" title="PATH on macOS / Linux">
  The installer appends a marked block to your login shell's rc file — `.zshrc` for zsh, `.bashrc` for bash (plus a `.bash_profile` that sources it on macOS), `config.fish` for fish, `.profile` for anything else:

  ```sh
  # >>> nittle >>>
  export PATH="$HOME/.nittle/bin:$PATH"
  # <<< nittle <<<
  ```

  Nothing else in the file is reordered or rewritten, the file is copied to `<rc>.nittle.bak-<timestamp>` before the first edit, and re-running the installer is a no-op. A child process can't change the shell that launched it, so run `exec $SHELL -l` (fish: `source <rc>`) to use `nittle` right away — new shells pick it up on their own.

  Set `NITTLE_NO_MODIFY_PATH=1` to skip the rc edit and print the `export` line instead, `NITTLE_NO_SETUP=1` to skip the agent setup prompt, or `NITTLE_DRY_RUN=1` to log every intended change without writing anything.
</Aside>

<Aside type="note" title="Windows PATH">
  `install.ps1` needs PowerShell 7 or newer. It edits only your **user** `PATH` (never the machine scope, and never the merged process value), backs the old value up to a timestamped file first, preserves every existing entry — `%VAR%` tokens included — and does nothing if `~\.nittle\bin` is already there. Set `NITTLE_NO_MODIFY_PATH` to install without touching `PATH`, `NITTLE_NO_SETUP` to skip the agent setup prompt, or `NITTLE_DRY_RUN` to print the plan and write nothing.
</Aside>

## Set up your coding agents

On a terminal, the installer finishes by asking `Set up nittle for your coding agents? [Y/n]` and runs `nittle setup`. It detects the agents you have installed, shows exactly what it will change, and asks before applying. You can run it any time, and `nittle setup --remove` undoes it. See [Agent feedback](/guides/agent-feedback/).

```sh
nittle setup
```

The prompt is skipped when there's no terminal, with `NITTLE_DRY_RUN`, or with `NITTLE_NO_SETUP=1`.

## Verify

<Steps>

1. Open a new terminal so `PATH` changes take effect.

2. Check the version:

   ```sh
   nittle --version
   ```

3. From any git repository, start a review:

   ```sh
   nittle
   ```

   nittle prints a `http://127.0.0.1:<port>` URL and opens it in your browser.

</Steps>

## Keep it current

```sh
nittle update
```

`nittle update` downloads the latest release, verifies its checksum, and swaps the binary in place (on Windows the swap completes as the process exits). If a package manager installed nittle, it prints that manager's upgrade command instead.

nittle also announces a new release in one line when you launch a review (at most one check a day); set `NITTLE_NO_UPDATE_CHECK=1` to silence it, or run `nittle update --check` to ask on demand.

## Uninstall

Remove the binary, and optionally your data directory. On a terminal, the uninstaller first runs `nittle setup --remove` so agents you wired up with `nittle setup` stop pointing at the deleted binary. Cancelling it stops the uninstall with the binary still in place; set `NITTLE_NO_SETUP=1` to skip it. Without a terminal, run `nittle setup --remove` yourself before uninstalling.

<Tabs syncKey="os">
  <TabItem label="macOS / Linux" icon="apple">
    ```sh
    curl -fsSL https://nittle.dev/install | NITTLE_UNINSTALL=1 sh   # binary + PATH block
    rm -rf ~/.nittle                                                # also removes review records + settings
    ```

    The uninstall step removes the `# >>> nittle >>>` block from your rc file and leaves the rest byte-identical. If you already have the script on disk, `sh install.sh --uninstall` does the same thing.
  </TabItem>
  <TabItem label="Windows" icon="seti:powershell">
    ```powershell
    $env:NITTLE_UNINSTALL = 1                 # the binary, and its user PATH entry
    irm https://nittle.dev/install.ps1 | iex
    Remove-Item -Recurse -Force ~/.nittle     # also removes review records + settings
    ```
  </TabItem>
</Tabs>

## From source (contributors)

nittle's server, CLI, and MCP runtime run on [Bun](https://bun.sh); the client is a built Svelte SPA.

```sh
git clone https://github.com/codywilliamson/diffle
cd diffle
bun install
bun run dev        # backend + Vite with /api proxied
```

<Aside title="Formerly diffle">
  nittle used to be called diffle, and before that loupe. If you have an older install, the first `nittle` run moves it over. See [Migrating from diffle](/guides/migrating-from-diffle/).
</Aside>
