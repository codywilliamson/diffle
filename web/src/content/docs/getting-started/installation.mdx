Install the `nittle` binary, connect it to your coding agents, and confirm it starts a review. nittle is one self-contained executable with its web client built in, so you need no checkout and no Node. The only prerequisite is `git` on your `PATH`.

## Install

<Tabs syncKey="os">
  <TabItem label="macOS / Linux" icon="apple">
    ```sh
    curl -fsSL https://nittle.dev/install | sh
    ```
  </TabItem>
  <TabItem label="Windows" icon="seti:powershell">
    ```powershell
    pwsh -c "irm https://nittle.dev/install.ps1 | iex"
    ```

    This needs PowerShell 7 or newer. Windows PowerShell 5.1 won't run it. Install PowerShell 7 with `winget install --id Microsoft.PowerShell --source winget`.
  </TabItem>
</Tabs>

The installer downloads the binary for your OS and architecture, checks its SHA-256 against the release's `checksums.txt`, and installs it to `~/.nittle/bin`. Then it adds that directory to your `PATH`.

The GitHub Releases installer is the only supported channel right now.

<Aside type="note" title="Coming from diffle">
  nittle used to be called diffle, and running this installer over a diffle install migrates your reviews, plugins, MCP configs and `PATH` entry in one pass. If anything can't move, both copies are kept and the [migration guide](/guides/migrating-from-diffle/) covers the rest.
</Aside>

The installer adds `~/.nittle/bin` to your shell rc file, or to your user `PATH` on Windows, and backs up what it edits. What it changes, and the `NITTLE_*` variables that move the install or skip a step, are in [Configuration](/reference/configuration/#path-changes-made-by-the-installers).

## Shell completions

On a terminal, the installer asks once, for example `Install nittle shell completions for zsh? [y/N]` (default no).

On macOS and Linux it works with zsh, bash and fish. On yes it adds one line inside the same `# >>> nittle >>>` block it wrote for `PATH`, so uninstalling removes it with the block. fish needs no profile edit: the installer writes `~/.config/fish/completions/nittle.fish` instead, and the uninstaller removes that file. If your rc has no nittle block (for example with `NITTLE_NO_MODIFY_PATH=1`), it prints the line and edits nothing.

On Windows it asks `Install nittle shell completions for PowerShell? [y/N]`. The installer never creates a block in your `$PROFILE`. If the profile already has a `# >>> nittle >>>` block, the line goes inside it. Otherwise the installer prints this line for you to add yourself:

```powershell
if (Get-Command nittle -ErrorAction SilentlyContinue) { nittle completion --shell powershell | Out-String | Invoke-Expression }
```

The offer is skipped when there's no terminal, with `NITTLE_DRY_RUN`, or with `NITTLE_NO_COMPLETIONS=1`. You can print the script for any shell later with `nittle completion --shell <bash|zsh|fish|powershell>` (see the [CLI reference](/reference/cli/)).

## Wire nittle into your coding agents

On a terminal, the installer ends by asking `Set up nittle for your coding agents? [Y/n]` and runs `nittle setup`. To do it yourself, or after installing a new agent, run:

```sh
nittle setup
```

`nittle setup` looks for the agents you have installed (a binary on `PATH` or a config directory). It installs the `nittle-review` plugin into Claude Code and Codex, and adds a `nittle` MCP server entry to Cursor, Gemini CLI, VS Code, Windsurf, OpenCode, Zed and GitHub Copilot CLI. It prints every command and file change first and asks `Proceed? [y/N]` before applying anything. Restart the agent or start a new session afterwards.

To pick agents without the checkbox prompt, pass their ids:

```sh
nittle setup --agents claude,codex --yes
```

`nittle setup --remove` undoes it. Without a terminal and without `--agents`, setup exits 1 and lists the agents it detected. The full table of agents and files is in [Agent feedback](/guides/agent-feedback/#set-up-your-agents).

You can skip this step entirely. `nittle --wait` hands feedback to any agent that can run a shell command, with no setup at all.

## Verify

<Steps>

1. Open a new terminal so the `PATH` change takes effect.

2. Check the version:

   ```sh
   nittle --version
   ```

   ```
   nittle v0.32.1
   ```

   If your shell says `nittle: command not found` (PowerShell: `The term 'nittle' is not recognized`), the new `PATH` hasn't loaded. Open another terminal, or on macOS and Linux run `exec $SHELL -l`.

3. From any git repository with uncommitted changes, start a review:

   ```sh
   nittle
   ```

   ```
   [nittle] v0.32.1 — reviewing working tree (1 file changed)
     http://127.0.0.1:47123/?review=8e27d1e1-43ea-419f-8235-1378e5e6606b  (ctrl+c to stop)
   ```

   Your browser opens on that URL. The port and review id differ on every run.

</Steps>

Next, follow the [Quickstart](/getting-started/quickstart/) to send your first review to an agent.

## Keep it current

```sh
nittle update
```

`nittle update` downloads the latest release, verifies its checksum, and swaps the binary in place. On Windows the swap completes as the process exits. It then stops idle MCP servers so your agents relaunch them on the new version, and prints the next steps that apply to you.

nittle also announces a new release in one line when you launch a review, checking at most once a day. Set `NITTLE_NO_UPDATE_CHECK=1` to silence it, or run `nittle update --check` to ask on demand.

## Uninstall

On a terminal, the uninstaller first runs `nittle setup --remove`, so agents you wired up stop pointing at the deleted binary. Cancelling that stops the uninstall with the binary still in place. Set `NITTLE_NO_SETUP=1` to skip it. Without a terminal, run `nittle setup --remove` yourself before uninstalling.

It removes the binary and its `PATH` entry and only removes empty directories. Your review records and settings stay in `~/.nittle` until you delete them.

<Tabs syncKey="os">
  <TabItem label="macOS / Linux" icon="apple">
    ```sh
    curl -fsSL https://nittle.dev/install | sh -s -- --uninstall   # binary + PATH block
    rm -rf ~/.nittle                                              # also removes review records + settings
    ```

    The uninstall removes the `# >>> nittle >>>` block from your rc file and leaves the rest byte-identical. If you already have the script on disk, `sh install.sh --uninstall` does the same thing. `NITTLE_UNINSTALL=1` works too.
  </TabItem>
  <TabItem label="Windows" icon="seti:powershell">
    ```powershell
    pwsh -c '$env:NITTLE_UNINSTALL = 1; irm https://nittle.dev/install.ps1 | iex'   # binary + user PATH entry
    Remove-Item -Recurse -Force ~/.nittle     # also removes review records + settings
    ```
  </TabItem>
</Tabs>

## Build from source

nittle's server, CLI and MCP runtime run on [Bun](https://bun.sh). The client is a built Svelte SPA.

```sh
git clone https://github.com/codywilliamson/nittle
cd nittle
bun install
bun run dev        # backend + Vite with /api proxied
```
