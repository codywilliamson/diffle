# Rewrite the client in Svelte 5 (Vite + Tailwind + shadcn-svelte); keep Bun

The buildless Preact + htm + esm.sh client no longer scales: the blanket line cap fragmented behavior, the root app coordinates too much through props, and browser components lack a typed test harness. We drop the no-build-step constraint. The client becomes a **Svelte 5 runes SPA** built with **Vite** and styled with **Tailwind v4 + shadcn-svelte**. We do **not** adopt SvelteKit because diffle is a locally launched, ephemeral review server with no SSR or application-routing need. We keep **Bun** as the server, CLI, MCP runtime, test runner, and standalone executable compiler.

Vite emits `dist/client`, which `Bun.serve` hosts without changing the browser API or the shared `src/types.ts` contract. A typed app-state factory creates the `diff`, `comments`, `review`, `prefs`, and `ui` rune modules; the app root exposes them through typed Svelte context helpers. This keeps the interface small and test-isolated without returning to prop drilling or process-global singleton stores. The durable Review Record remains the authoritative state across reviewer writes and agent polling.

The `evolve` branch makes the Svelte client the default as soon as the Phase 0 scaffold lands. The Preact source remains only as read-only parity evidence until the replacement covers its behavior; the branch does not carry a fallback, feature flag, or requirement that both clients run. Development is test-driven in vertical slices: one failing behavior test, the minimum implementation that makes it pass, then the next slice. The agreed seams are `bun test` for core/server interfaces, Vitest for pure client and typed HTTP behavior, Testing Library for Svelte user interactions, and Playwright for browser-level launch and review workflows. Playwright supplies tracer bullets through the real app; it does not duplicate every lower-level assertion.
