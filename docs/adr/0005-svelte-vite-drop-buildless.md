# Rewrite the client in Svelte 5 (Vite + Tailwind + shadcn-svelte); keep Bun

The buildless Preact + htm + esm.sh client no longer scales (fragmented modules split by the 200-line cap, prop-drilling god-component, no component test coverage), so we drop the no-build-step constraint. The client becomes a **Svelte 5 (runes) SPA** built with **Vite**, styled with **Tailwind v4 + shadcn-svelte** (Bits UI headless primitives, fully restyled to the bodkin palette). We do **not** adopt SvelteKit — bodkin is a locally launched, ephemeral, per-review server with a separate stdio MCP mode and no routing/SSR need, which SvelteKit is the wrong shape for. We **keep Bun** as the server/CLI/MCP runtime and the binary compiler: `bun build --compile` is the linchpin of zero-friction cross-platform distribution, and moving to Node (SEA/pkg) would make that harder, not easier. Vite emits static assets that `Bun.serve` hosts (`clientDir` points at the build output instead of `src/client`); the server API and `src/types.ts` contract are preserved unchanged. Client state moves to domain-scoped rune stores (`diff`, `comments`, `review`, `prefs`, `ui`) that components import directly, replacing the `app.js` prop-drilling. Testing becomes three-tier: `bun test` for the pure core/server modules, Vitest + `@testing-library/svelte` for components (closing the "green tests, blank UI" gap), and Playwright for one end-to-end smoke.
