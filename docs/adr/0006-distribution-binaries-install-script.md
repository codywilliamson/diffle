# Distribute prebuilt binaries via an install script and GitHub Releases

bodkin targets public-OSS adoption, cross-platform (Windows/macOS/Linux), MCP-first, and today's install secretly requires cloning the repo and `bun link` (the agent plugins just run `bodkin mcp serve` and depend on the CLI being on PATH). We sever that. The **primary install channel** is a one-line install script (`curl -fsSL https://bodkin.sh/install | sh` on macOS/Linux, `irm https://bodkin.sh/install.ps1 | iex` on Windows, hosted on the bodkin Cloudflare domain) that detects OS/arch, downloads the matching Bun-compiled binary from the latest GitHub Release, and puts `bodkin` on PATH; **package managers** (Homebrew tap, Scoop bucket, winget) are a fast-follow; clone + Bun is demoted to the contributor/from-source path. For agents: Claude Desktop gets a **self-contained MCPB bundle** built per-OS (binary inside) and attached to every Release, while the Claude Code and Codex plugins keep their lightweight `.mcp.json` and rely on the install script for the binary. A **tag-triggered GitHub Actions matrix** builds the three binaries and three MCPBs, emits checksums, and cuts the Release. `bodkin update` self-replaces script-installed binaries and defers to the package manager when the binary was installed that way.
