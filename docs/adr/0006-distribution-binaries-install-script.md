# Distribute self-contained executables through an install script and GitHub Releases

diffle targets public OSS adoption across Windows, macOS, and Linux, but today's install requires a clone plus `bun link`. The primary install channel becomes a one-line script hosted on the approved diffle Cloudflare domain. It detects OS and architecture, downloads the matching GitHub Release asset and checksum manifest, verifies SHA-256, and installs `diffle` into a user-writable location with PATH guidance. Homebrew, Scoop, and winget follow after this path is proven; clone plus Bun remains the contributor path.

Each executable embeds the Vite-built client with Bun's standalone file-asset imports and receives its version at build time. The build enumerates Vite output and generates a deterministic static-import manifest; this works with the repository's current Bun 1.3.14, whose CLI does not yet expose the newer `compile.assets`/`--asset` interface. The executable must run outside a checkout without `package.json` or web-asset sidecars. The release matrix explicitly covers Windows x64/arm64, Linux x64/arm64, and macOS x64/arm64. Claude Desktop receives one self-contained MCPB per target containing that same executable; Claude Code and Codex plugins remain thin and call the installed command.

The installer publishes a checksum or release-attestation manifest and replaces files atomically. `diffle update` uses the same verified path; on Windows it completes replacement from an after-exit helper. Package-manager installs refuse self-replacement and print the correct manager command. Update checks use the release channel plus the embedded version and fail quietly when offline.

Release Please owns Conventional Commit analysis, the release PR, version and changelog updates, the `vX.Y.Z` tag, and draft GitHub Release creation. Merging its release PR is the explicit release approval. Configure `draft: true` with forced tag creation; the project-owned cross-platform build, MCPB, checksum/attestation, and installer jobs run downstream of Release Please's `release_created` output, upload into that draft, and publish it only after every required job succeeds. Release Please does not replace those build jobs. Keeping everything in one workflow also avoids relying on a second workflow event that GitHub suppresses when the built-in `GITHUB_TOKEN` creates the release. Deploying installers or changing external identity remains separately approved.
